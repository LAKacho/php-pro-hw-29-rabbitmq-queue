# ДЗ 29. Обработка отложенных запросов через RabbitMQ

Учебное веб-приложение принимает заявку на банковскую выписку, немедленно сообщает пользователю о постановке в очередь, а длительную работу выполняет отдельный процесс. После обработки результат сохраняется, а уведомление отправляется по email.

## Архитектура

```text
браузер -> PHP web -> RabbitMQ -> PHP worker -> генератор выписки
                    быстрый ответ             |-> хранилище статусов
                                              `-> Mailpit (email)
```

- `web` — форма, валидация, публикация сообщения и страница статуса;
- `rabbitmq` — durable-очередь `statement_requests`;
- `worker` — консольный обработчик с ручным `ack` после успешной работы;
- `mailpit` — безопасный локальный SMTP-сервер и интерфейс просмотра писем;
- Docker volume — общее учебное хранилище статусов и результатов.

Сообщения публикуются с `delivery_mode=2`, очередь объявлена durable. Worker использует `prefetch=1`, поэтому не забирает пачку тяжёлых задач заранее. Подтверждение (`ack`) отправляется только после генерации, сохранения результата и попытки уведомления.

## Требования

- Docker Desktop с Docker Compose;
- свободные порты `8080`, `8025` и `15672`.

PHP, RabbitMQ и SMTP отдельно устанавливать не нужно.

## Запуск

Из каталога проекта выполнить:

```bash
docker compose up --build -d
```

Открыть:

- приложение: <http://localhost:8080>;
- полученные письма: <http://localhost:8025>;
- RabbitMQ Management: <http://localhost:15672> (`app` / `secret`).

Логи обработчика, требуемые условием задания:

```bash
docker compose logs -f worker
```

В них выводятся номер заявки, период, email и результат обработки.

Остановка:

```bash
docker compose down
```

Удаление контейнеров вместе с учебными результатами:

```bash
docker compose down -v
```

## Проверка сценария

1. Открыть форму и указать email и корректный диапазон дат.
2. Нажать «Сформировать выписку» — сразу появятся подтверждение и номер заявки.
3. Перейти по ссылке статуса. Пока worker работает, страница обновляется раз в 3 секунды.
4. Убедиться, что статус стал `completed` и показан итоговый баланс.
5. Открыть Mailpit и проверить письмо «Банковская выписка готова».
6. Проверить консоль worker командой из раздела запуска.

## Обработка ошибок

- Форма проверяет CSRF-токен, email, обе даты, их порядок и запрет будущей даты.
- Запись статуса выполняется атомарно через временный файл и `rename`.
- Некорректное сообщение не подтверждается worker-ом и фиксируется в stderr.
- Идентификатор в URL проверяется по строгому шаблону, поэтому выйти за каталог хранилища нельзя.

## Преимущества и недостатки очереди

Пользователь не ждёт генерацию выписки, нагрузку можно масштабировать добавлением worker-ов, а RabbitMQ отделяет приём HTTP-запроса от обработки. Цена этого решения — дополнительная инфраструктура, eventual consistency (результат появляется не сразу), необходимость наблюдать за очередью и продумывать повторную обработку. Для production-версии стоит добавить retry с ограничением попыток, dead-letter queue, идемпотентность по `message_id`, базу данных вместо файлов и внешнего почтового провайдера.
